## Requirements

- **Node.js 20+** when you install the package with a bundler or run it on the server. The builds target ES2020.
- Any package manager, or no package manager at all when you load the standalone script from a CDN.

## Install

<Installer />

The **HTML / CDN** tab loads the minified standalone build with phone support, which defines `window.Formatter` with `format`, `intl`, `regex`, `checks` and `version`. Pages that format no phones can load the smaller `formatter.global.js` instead; see [HTML / CDN](../reference/browser/).

Phone support is opt-in since 3.0.0 so bundles that never format phones skip `libphonenumber-js`. With a package manager, import `registerPhone` from `@samline/formatter/phone` and call it once, as below.

## Quick start

```ts
import { format } from '@samline/formatter'
import { registerPhone } from '@samline/formatter/phone'

registerPhone()

// Phone (Mexico by default, space-delimited)
format('5512345678', 'phone')
// => { formatted: '55 1234 5678', raw: '5512345678', type: 'phone' }

// Numeral (thousand separators)
format('1234567', 'numeral')
// => { formatted: '1,234,567', raw: '1234567', type: 'numeral' }

// Date (a raw Y-m-d value becomes d/m/Y for display)
format('2026-05-12', 'date')
// => { formatted: '12/05/2026', raw: '2026-05-12', type: 'date' }

// Credit card (grouped by brand, digits-only raw)
format('4111111111111111', 'creditCard')
// => { formatted: '4111 1111 1111 1111', raw: '4111111111111111', type: 'creditCard' }

// Card brand detection
format('4111111111111111', 'creditCardType')
// => { formatted: 'visa', raw: '4111111111111111', type: 'creditCardType' }
```

<Callout title="Two outputs in one call">
  Every call returns a `FormatterResult` with `formatted` (display) and `raw` (backend). Pair the
  visible input with a hidden input and mirror `raw` into it, so the form always submits the
  canonical value.
</Callout>

## Ownership

Formatter owns nothing on the page. Your code owns the listener, the visible value, the hidden value, labels, error messages and caret handling. There is no instance to create or destroy: remove your own listener when the field goes away. The [Styling and UX guide](../guides/styling-and-ux/) covers markup, input attributes and caret behavior.
