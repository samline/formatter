Each example is a real form field. The preview, the copied files and the Home demo share one scenario definition, so the options shown in code are the options running in the preview. Type into the field, try the sample values, then open the code.

Open the code under each example to copy its files. They run in two loading modes. **HTML / CDN** files work after saving them to one folder and opening `index.html` (network access to unpkg is required). **Package / ESM** files import `@samline/formatter` and need a bundler or dev server such as Vite.

## Phones

### Phone by country

`format(value, 'phone', { country })` groups digits for the selected country through `libphonenumber-js`. Phones are opt-in: the copied ESM file calls `registerPhone()` from `@samline/formatter/phone`, and the CDN file loads `formatter.phone.global.js`; every other example uses the smaller core script. Changing the country reformats the current digits; the listener reads the country on every call instead of being re-attached.

## Numbers and money

### Amount with currency

The `numeral` type adds grouping, a prefix and a decimal limit. `raw` is a plain decimal string without the prefix. `regex.numeral(options)` takes the same options as `format()`, so the rule accepts exactly what the mask writes: `$1,234.` (decimal mark last) fails until a decimal is typed.

<Playground preset="amount" showCode />

### European price

`numeralDecimalMark: ','` and `delimiter: '.'` switch the separators, and `tailPrefix: true` moves the currency to the end. The raw value still uses a dot. The same options passed to `regex.numeral(options)` check the comma, the dots and the trailing ` €` of the visible value.

<Playground preset="euro" showCode />

### Whole positive quantity

`numeralDecimalScale: 0` and `numeralPositiveOnly: true` produce integer counts with no sign. Leading zeros are removed.

<Playground preset="quantity" showCode />

## Dates and times

### Date for display, ISO for storage

`dateRawPattern` and `dateRawPatternDelimiter` decide the raw shape independently of the display pattern. The default `interpretInputAs: 'auto'` converts a stored `1990-12-31` for display.

<Playground preset="date" showCode />

### Card expiry

`datePattern: ['m', 'y']` builds an MM/YY mask and corrects impossible months. Pair it with `regex.expirationDate`.

<Playground preset="expiry" showCode />

### Appointment time

`timePattern: ['h', 'm']` shows hours and minutes. The raw value is validated with `regex.time24`.

<Playground preset="time" showCode />

### Date tools in any language

The mask writes `DD/MM/YYYY`; `parseDate` from `@samline/formatter/date` reads it back with the same tokens and `formatDatePattern` shows the weekday (`dddd`), the long date (`LL`) and the ISO week (`WW`) in the selected locale. `parseDate` is strict, so it returns `undefined` until the date is complete and real, and `regex.date(options)` reports the same state for the visible value. The copied ESM file imports `@samline/formatter/date`; the CDN file loads `formatter.date.global.js` after the core script and reads `window.Formatter.date`. See [Date tools](../../reference/date/) for every function.

<Playground preset="weekday" showCode />

## Custom masks

### Locked prefix

The `general` type needs `blocks`. A locked `prefix` is displayed on every call, restored after a single deletion and excluded from `raw` unless `rawPrefix: true`.

<Playground preset="reference" showCode />

### Unit suffix

`suffix` adds a trailing decoration. In the default lock mode, deleting part of it restores the full suffix.

<Playground preset="weight" showCode />

### Passthrough prefix

`prefixMode: 'passthrough'` keeps the prefix people type, in any case when `uppercase` is set, instead of adding it for them.

<Playground preset="promo" showCode />

### ZIP code with optional block

`delimiterLazyShow: true` shows the hyphen only when the second block starts. Pair it with `regex.postalCode`.

<Playground preset="postal" showCode />

### Postal code by country

Postal codes have no single shape, so this field uses the `text` type with `case: 'upper'` instead of a mask, and the country select builds the rule with `regex.postalCode({ country })`. 24 countries are built in; the static `regex.postalCode` stays the US ZIP, and other countries use `regex.custom()`.

<Playground preset="postcode" showCode />

### Uppercase identifier

`uppercase: true` transforms the display, and `raw` follows it because there is no decoration. `regex.curp` checks the structure (date, sex, state and inner consonants) and `isValidCurp` the final check digit, so **Wrong check digit** passes the pattern and still fails. The CDN file reads `isValidCurp` from `window.Formatter.checks`.

<Playground preset="curp" showCode />

### Prefix kept in raw

`rawPrefix: true` stores the `#` with the value, so the backend receives a complete CSS color.

<Playground preset="color" showCode />

## Validation

### IBAN with check digits

The mask groups the IBAN in fours as it is printed, and `raw` drops the spaces. `regex.iban` checks the shape; `isValidIban` checks the length for the country and the mod 97 check digits, so **One digit wrong** fails although its shape is valid. The check-digit validators ignore spaces and hyphens and do not import `regex`.

<Playground preset="iban" showCode />

### Validation rules

Pick a rule from the `regex` catalog. Static entries are records; parametric entries such as `password()` are called first. Every rule pairs its pattern with its message. `regex.phone` allows spaces, hyphens, dots, parentheses and `+` between the digits, but no letters: **Letters between digits** (`abc5512345678`) fails since 3.2.0.
