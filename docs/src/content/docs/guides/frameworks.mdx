`@samline/formatter` is framework-agnostic by design. The visible input, the hidden mirror, and the error message are always wired through the same `input` listener; the framework owns the state.

This guide shows the recommended wiring for every common runtime. Each snippet is self-contained — drop it into a project and adapt it to your conventions.

## The pattern

The shape is always the same:

1. Two inputs in the DOM: the visible one the user types in, and a hidden mirror that carries the canonical raw value.
2. One `input` listener that calls `format()` and writes the result to both inputs.
3. Framework-owned state when you need it (controlled inputs, refs, etc.).

```ts
import { format } from '@samline/formatter'
import { registerPhone } from '@samline/formatter/phone'

registerPhone()

const apply = () => {
  const { formatted, raw } = format(input.value, 'phone')
  input.value = formatted // visible
  hidden.value = raw // submitted with the form
}
input.addEventListener('input', event => {
  if (event.isComposing) return // an IME is composing: rewriting the value would cancel it
  apply()
})
input.addEventListener('compositionend', apply) // format once the IME commits
```

That listener pair is the entire pattern. Skip `input` events while `event.isComposing` is true and format once on `compositionend`, or Japanese, Chinese and Korean input loses its candidate text; the other snippets on this page leave that guard out for brevity, so add it to yours. The rest of this page shows how each framework wraps it without losing the contract.

```tsx title="PhoneField.tsx"
import { useState } from 'react'
import { format } from '@samline/formatter'
import { registerPhone } from '@samline/formatter/phone'

registerPhone()

export function PhoneField({ name, country = 'MX' }: { name: string; country?: string }) {
  const [display, setDisplay] = useState('')
  const [raw, setRaw] = useState('')

  return (
    <>
      <input
        type="text"
        inputMode="tel"
        autoComplete="tel"
        value={display}
        onChange={e => {
          const { formatted, raw } = format(e.target.value, 'phone', { country })
          setDisplay(formatted)
          setRaw(raw)
        }}
      />
      <input type="hidden" name={name} value={raw} readOnly />
    </>
  )
}
```

Both values live in React state, so the visible input and hidden mirror update in the same render without direct DOM mutation.

<TabPanel id="vue-3" label="Vue 3">

```ts title="use-formatted.ts"
import { computed, ref } from 'vue'
import { format } from '@samline/formatter'
import type { FormatOptions, FormatType } from '@samline/formatter'

export function useFormatted(
  initial = '',
  formatType: FormatType = 'general',
  options: FormatOptions = {}
) {
  const display = ref(initial)
  const raw = computed(() => format(display.value, formatType, options).raw)

  function onInput(event: Event) {
    const target = event.target as HTMLInputElement
    display.value = format(target.value, formatType, options).formatted
  }

  return { display, raw, onInput }
}
```

```vue title="PhoneField.vue"
<template>
  <input :value="display" @input="onInput" inputmode="tel" autocomplete="tel" />
  <input type="hidden" name="phone" :value="raw" />
</template>

<script setup>
import { useFormatted } from './use-formatted'
// registerPhone() from '@samline/formatter/phone' runs once in main.ts.

const { display, raw, onInput } = useFormatted('', 'phone', { country: 'MX' })
</script>
```

`raw` is reactive — wherever you read it downstream (a watcher, a computed, a template binding) you always see the latest canonical value.

<TabPanel id="svelte" label="Svelte">

```svelte title="PhoneField.svelte"
<script>
  import { format } from '@samline/formatter'
  import { registerPhone } from '@samline/formatter/phone'

  registerPhone()

  let display = ''

  $: raw = format(display, 'phone', { country: 'MX' }).raw

  function onInput(event) {
    display = format(event.target.value, 'phone', { country: 'MX' }).formatted
  }
</script>

<input
  type="text"
  inputmode="tel"
  autocomplete="tel"
  value={display}
  on:input={onInput}
/>
<input type="hidden" name="phone" value={raw} />
```

Svelte's reactive `$:` block keeps the hidden mirror in lockstep with the visible field. Update `display` → `raw` recomputes → the `<input type="hidden">` re-renders.

```ts title="format-server.ts"
import { format } from '@samline/formatter'
import { registerPhone } from '@samline/formatter/phone'

registerPhone()

// Normalize a phone number coming from a CRM webhook
const stored = format('+525512345678', 'phone', { country: 'MX' })
// stored.formatted: '+52 55 1234 5678'
// stored.raw:       '+525512345678'

// Render an "amount due" string in a transactional email
const invoice = format('123456', 'numeral', { prefix: '$', delimiter: ',' })
// invoice.formatted: '$123,456'
// invoice.raw:       '123456'
```

`format()` is pure — call it from a queue, a webhook handler, an email renderer, anywhere JavaScript runs. There is no client-side limit.

## Astro

Use a processed client `<script>` in the `.astro` file, not the frontmatter: the listener needs the input. Without client navigation, attach it once. With `<ClientRouter />`, attach on `astro:page-load` and abort on `astro:before-swap`, so listeners never outlive their page.

```astro
<input id="phone" type="text" inputmode="tel" autocomplete="tel" />
<input id="phone_raw" type="hidden" name="phone" />

<script>
  import { format } from '@samline/formatter'
  import { registerPhone } from '@samline/formatter/phone'

  registerPhone()

  let lifetime: AbortController | undefined

  // astro:page-load fires only with <ClientRouter />. Without client navigation, run this setup once at the top level.
  document.addEventListener('astro:page-load', () => {
    lifetime = new AbortController()
    const phone = document.querySelector<HTMLInputElement>('#phone')
    const phoneRaw = document.querySelector<HTMLInputElement>('#phone_raw')
    if (!phone || !phoneRaw) return

    phone.addEventListener(
      'input',
      () => {
        const { formatted, raw } = format(phone.value, 'phone', { country: 'MX' })
        phone.value = formatted
        phoneRaw.value = raw
      },
      { signal: lifetime.signal }
    )
  })
  document.addEventListener('astro:before-swap', () => lifetime?.abort())
</script>
```

## Shopify

Copy `dist/browser/formatter.phone.global.js` of the pinned release into the theme's `assets/` folder (use `formatter.global.js` when you do not format phones) and load it once in `layout/theme.liquid`. It defines `window.Formatter` with `format`. Add `formatter.date.global.js` after it only if you need the date tools.

```liquid
<script src="{{ 'formatter.phone.global.js' | asset_url }}" defer></script>
```

The theme editor adds and removes sections without a page load, so attach the listener on `shopify:section:load` and abort it on `shopify:section:unload`. `event.target` is the section element. Run `mount` once for the sections already on the page.

```js
const lifetimes = new Map()

const mount = root => {
  const phone = root.querySelector('input[type="tel"]')
  if (!phone) return
  const lifetime = new AbortController()
  lifetimes.set(root, lifetime)

  phone.addEventListener(
    'input',
    () => {
      const { formatted } = window.Formatter.format(phone.value, 'phone', { country: 'MX' })
      phone.value = formatted
    },
    { signal: lifetime.signal }
  )
}

document.addEventListener('shopify:section:load', event => mount(event.target))
document.addEventListener('shopify:section:unload', event => {
  lifetimes.get(event.target)?.abort()
  lifetimes.delete(event.target)
})
document.addEventListener('DOMContentLoaded', () => {
  document.querySelectorAll('.shopify-section').forEach(mount)
})
```

Shopify's own forms post the visible value. When your backend needs the canonical number, write `raw` to a hidden input as in the Vanilla tab. See [Shopify's section events](https://shopify.dev/docs/storefronts/themes/best-practices/editor/integrate-sections-and-blocks).

## WordPress

Enqueue the pinned classic script from your theme or plugin, deferred, on the front end. `'strategy' => 'defer'` needs WordPress 6.3 or newer.

```php
add_action('wp_enqueue_scripts', function () {
  wp_enqueue_script(
    'samline-formatter',
    'https://cdn.jsdelivr.net/npm/@samline/formatter@3.3.2/dist/browser/formatter.phone.global.js',
    [],
    null,
    ['strategy' => 'defer', 'in_footer' => true]
  );
  wp_enqueue_script(
    'my-phone-field',
    get_theme_file_uri('assets/phone-field.js'),
    ['samline-formatter'],
    null,
    ['strategy' => 'defer', 'in_footer' => true]
  );
});
```

`assets/phone-field.js` is your own file. Declaring `samline-formatter` as its dependency keeps the order, so `window.Formatter` exists when it runs:

```js
const phone = document.querySelector('input[type="tel"]')

phone?.addEventListener('input', () => {
  const { formatted } = window.Formatter.format(phone.value, 'phone', { country: 'MX' })
  phone.value = formatted
})
```

The script targets the content it finds on the page; widgets or AJAX-loaded forms need to run it again after they render. See [wp_enqueue_script](https://developer.wordpress.org/reference/functions/wp_enqueue_script/).

## Pairing with `@samline/forms`

When you use `@samline/forms` for validation and submit handling, prefer the controller's own `format()` / `formatAll()` method. It wraps the same plumbing, renames the visible to `<field>_displayed`, creates the hidden mirror, and respects the `'auto'` / `'display'` interpretation per source.

See [the `@samline/forms` documentation](https://github.com/samline/forms) for the full mirror lifecycle and the `FieldFormatConfig` options.

## Pitfalls

- **Reading `e.target.value` twice.** Some frameworks expose the input event with a value already mutated by your handler. Capture `target.value` into a variable before the second read.
- **Re-running `format()` on the same raw.** The formatter is pure and cheap, but if you reach for it from a heavy render path, debounce the listener instead. The bottleneck is your framework's re-render, not the formatter.
- **Swapping `formatted` and `raw` in the hidden mirror.** The visible is `formatted`; the hidden is `raw`. Mixing them up ships the formatted value (`55 1234 5678`) to the backend, which then has to re-parse it.
- **Forgetting `country` on `phone`.** The default is `'MX'`. If your users are international, drive `country` off a `<select>`'s change event.
- **Pasting an eight-digit string into a date field.** The auto-detection heuristic routes that as raw by default. Force `interpretInputAs: 'display'` if your pipeline only sees user-typed input — see [`format(…, 'date')`](../../reference/configuration/#date).
